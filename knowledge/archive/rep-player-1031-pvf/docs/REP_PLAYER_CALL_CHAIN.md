# REP Player 与 1031 技能调用链

状态：分析与来源入口已整理；战斗因果链仍在逆向中。本文件区分已证实、合理推理和未知，不把预览画面当作命中证据。

## 两类 `.rep` 不是同一种格式

86JP `Replay/SkillReplay` 中的 `.rep` 是录像协议。`src/protocol.cpp` 读取录像头、版本、资源字典和压缩时间线；`src/engine.cpp` 按场景时间戳执行已经记录的绘制/状态指令；`src/resources.cpp` 从 `ImagePacks2` 定位 NPK/IMG；`src/bindings.cpp` 绑定录像记录的 shader 参数；音频由独立音频轨扫描和播放。`src/ui_playback.cpp` 负责加载、开始、暂停、拖动和逐帧定位。

因此，REP Player 当前完整恢复的是“已记录的表现如何重放”：某时刻引用什么 IMG、帧号、位置、图层、相机、裁剪、混合、shader 或声音事件。它没有推进 1031 的技能资格、角色控制器、NUT 脚本、ACT/ANI、攻击框、目标选择、ATK 伤害、怪物 HP 或受击状态。

清风 1031 PVF 中的 `.rep` 位于 `etc/pvppracticecombo/replay`，内容是 token5 `ScriptFile`。目前核对的 484 个成员与 86JP 录像协议不同；REP 协议解码器将其视为无效文件长度。脚本中的 `[skill key]` 是输入/快捷栏关联数据，不能证明该次输入成功执行或命中。`rep_pvf.exe` 现在走 PVF 索引与 ScriptFile 解码路径，不调用 `rep::Replay`。

## PVP UI 表现链

86JP `Replay/PVP/PracticeCombo` 的录像里包含 PVP 界面绘制。它不是独立 UI 树，而是与地图、角色、特效共同保存在按时间戳排序的绘制命令时间线中。REP Player 读取每条场景的命令 ID 和辅助坐标，再按指令顺序处理 IMG 路径/帧、图层、混合、裁剪及文字字形。没有一个 opcode 单独代表“UI”；界面对象需结合资源路径、帧、位置和图层识别。

当前已批量解析 751/751 条 86JP PVP 录像：REP 1.0 有 656 条、REP 1.1 有 95 条，全部 minor 0，零错误。代表 `Swordman/0/01.rep` 为 800×600、266 个场景、63,463 次命令引用，时间线至 4,692 ms。样本实际引用 `Sprite/Interface/PVP.img`、`interface2/HUD/HUD.img`、`SkillBuyWindow.img`、`keyshortcut.img`、PVP tournament/rank/practice 图片和 `UI/SkillShop/SkillShop.img` 等资源；字典中的绘制模板数不等于播放时实际绘制次数。

文字绘制由 opcode 5（旧录像）或 opcode 48（较新格式）进入字体路径。`Fonts::parameters` 解析文字类型、样式、颜色等；`Fonts::prepare` 从录像资源表取文本，用客户端 `Fonts` 字体栅格化成字形，再交由 `Executor` 依照坐标/图层和渲染状态绘制。86JP 样本需显式用 CP949 解码，系统默认活动代码页会把韩文文字读成乱码。

用户已把“菜单”“商城”指定为字体复刻目标。代表录像及 54 个 `01.rep` 样本的 723 条文字绘制引用没有包含这两个词或对应英文；当前能确认的是文字指令到字形绘制的调用链，不能用这些录像证明目标文字的原版字形、字体文件或字号/描边参数。其他文字暂时不进入复刻目标。单独报告见 [PVP_UI_AND_FONT_SCOPE.md](PVP_UI_AND_FONT_SCOPE.md)。

PVP REP 可作为界面外观和绘制顺序的参考，不等于当前 1031 PVF 内容。它不能证明菜单状态、商城业务或按键交互；而当前 1031 PVF 连招 `.rep` 不能当作这种 UI 时间线直接回放。后续独立预览须从当前 1031 PVF/静态资源读取实际内容，再将确认可对应的 UI 绘制能力接入；86JP 数据不直接作为 1031 内容常量。

## 技能到怪物结果的目标链

```text
玩家输入 / 连招练习输入
    -> 职业身份、技能表与快捷栏绑定
    -> 学习等级、状态、模式、MP、CD、指令等释放资格
    -> 职业技能控制器与 NUT 宿主调用
    -> 状态请求 / ACT 行为 / 动画实例
    -> ACT base ANI、sub ANI、ALS 附层、PTL/被动对象和声音事件
    -> 当前帧攻击框、目标当前帧受击框、方向/XYZ变换、资格门
    -> 命中接受、去重/多段周期、ATK实例与伤害结算
    -> 怪物 HP 与状态变化
    -> 怪物受击、浮空、倒地、霸体/无敌、死亡 ACT/ANI/PTL 与清理
```

这条链是调查框架，不能假设每个技能都按完全相同的子步骤执行。某些技能可能由 ACT/NUT 触发多个实体或多个攻击阶段；每个技能需要用其职业、控制器和资源来源逐项填表。

## 每个技能的证据记录要求

技能矩阵必须按“职业身份 + 技能 ID + PVF 成员路径 + 成员 SHA-256”唯一标识，并分别记录：输入来源、资格门、NUT 函数/参数、状态/ACT 请求、ANI 与 ALS 依赖、攻击阶段/盒/ATK、受击目标状态、怪物响应 ACT/ANI/PTL、清理条件、自动验证、用户画面验证、原版对照。每个字段标为 `confirmed`、`inferred`、`unknown` 或 `user-test-only`；资源同名、文件存在或录像中看到效果不能升级证据等级。

本项目下一步先完成通用 PVF/技能依赖索引，再按代表技能逐项追查 NUT 调用与 ACT/ANI/ATK 事件，最后制作 PVF 驱动的隔离预览。预览将重放来源动作和效果，不会在因果证据闭合前声称复现了怪物命中或伤害逻辑。
