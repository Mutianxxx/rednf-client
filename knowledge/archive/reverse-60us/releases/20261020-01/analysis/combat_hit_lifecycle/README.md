# 60US 攻击命中记录与重置时机

当前字节已确认：攻击历史不是按 ANI 帧自动清空。四个已核对的虚表（Swordman、Monster、Generic PassiveObject、ReleaseWave）都将 `+1A0` 绑定到 `438990`，它分别对 `entity+418` 与 `entity+470` 调用 `4389B0`，清理命中历史和重复攻击计时表。

`+198` 是攻击信息安装链的一部分。Swordman 走 `746C30 → 4CF680 → 4AFA10 → 4EDCD0`；Monster 走 `4AFA10 → 4EDCD0`；当前两个 PassiveObject 虚表直接使用 `4EDCD0`。`4EDCD0` 在参数为 null 时初始化 `+260`，非 null 时 `4A27E0` 复制 ATK，**两个分支都调用 `+1A0`**。因此重新安装同一 ATK 也开始新的历史区间，不能仅按 ATK 指针是否改变决定是否清空。

普通鬼斩 `731FCA` 与三段斩 `732B60` 都调用这个 `+198` 槽。三段斩安装新段攻击信息因此确实有清理机会；这不等同于任意身体 ANI 切帧都会清理。三段斩 tick 另有 `729B56 → A51FB0` 成功后 `729B75 → +1A0` 的主动清理点，其计时器初始化/完整触发周期仍待合并证明，不能删掉这条路径来假装每段只命中一次。

`4ED140` 的实体重置同样调用 `+1A0`。它后续调用的 `+298=438710` 只把 pending state `+4A0` 设为 -1，不能把 `+298` 错认成历史清理槽。

历史还会通过 `+1C8` 返回的归属实体共享：`4ECE50` 查询时，若 attacker 的 `+1C8()` 不是自己，转发给该实体的 `+1A8(target)`；否则以 **target 的 `+1C8()`** 为 key 查询自身 `+418`。`4EDE20` 注册走同样的 attacker 转发，并写入 target 的归属 key；target 与其归属不同还补写 target 自身 key。后续重建必须保留归属关系，不能简单为每个生成特效维护互不关联的集合。

mode 2 的重复攻击由 `4EDEB0` 另查 `+470`。未命中过时记录当前 `entity+60 → B06F00()`；已命中过时，只有表中有该 target 且有符号差值 `now-previous >= 1000` 才清除传入的 seen 标记并更新时间。这是资格过滤中的局部分支，尚未等同完整命中接受。`4EE130` 在 emit 分支先 `+1A4` 注册历史，再 `4EABF0` 写出 opcode `0x13`；不要等目标扣血成功才登记。

场景移除通知 `4EDD10(target)` 会删除两张表里的 target key；self 通知还清理两张整表。这与攻击安装、计时清理是不同触发点。

证据保存在 [evidence-index.json](evidence-index.json)、原始 `.bin` 与对应 `.asm`，可用 `build_evidence.py` 对当前 PE 重建。REA 的反编译作为补充保留原 Evidence ID，不替代 x86 字节核对。没有运行原客户端验证这些分支；也尚未完成所有生成物的 `+1C8` 归属安装、全部主动重置点与最终命中门控。预览当前仍只报告几何接触，不据此自动扣血或切怪物状态。
