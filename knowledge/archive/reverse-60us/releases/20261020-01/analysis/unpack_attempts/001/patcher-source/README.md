## 技能消费链的新边界

此前选定的 Swordman skill 5 / HardAttack 消费入口为 `72ACF3 → vslot 768=4C1D30 → 4D9040`。本次将命令/消费/状态请求片段、消费包装、消费主体至保护跳板、成功返回尾部、挂起状态请求主体和网络提交函数共六段字节，与旧 v3 备份比较，全部相同。逐范围哈希见 [skill-consume-runtime-contract.json](skill-consume-runtime-contract.json)。

走到 `4D96A7` 的特定分支时，主体组装 opcode `0x29`，写一字节参数及由 `550BD0` 返回的两字节值；`4D96F1` 跳到已被启动器改写的 `13B37C2`。现有兼容逻辑调用 `A5F4A0` 后跳到 `4D9758`，由尾部返回 `AL=1; ret 0x10`。`A5F4A0` 内 UTF-16 日志明确提到 `[network]`、packet 和 send lock；这里识别的是代码语义，没有宣称已抓到数据包。

这闭合了当前启动版本的一条消费尾部路径，不能证明它等价于原 VM 内全部逻辑。六段字节相同也不能证明用户这次具体技能执行了这些片段，间接调用内部和其他条件仍未完全覆盖。

## 怪物替代入口的执行证据

替代代码检查输入对象 `+E8` 的 `0x211` / `0xF000`，维护自己的调用计数、分支计数和间隔条件。一条分支构造 opcode `0x2A` 并提交；另一条调用输入对象 vtable `+60(0)` 后把 `+184` 写零；最后返回成功。这些是补丁程序的实现，不能直接命名为原版死亡算法。

[只读状态采样](../launcher_test/live-56460-20261019T150836Z/hook-state-observation.json)再次核对了进程创建时间、路径、磁盘哈希、入口目标及代码一致性。采样时调用计数 `3770404=370`，分支计数 `3770408=8`，最近包装值 `3770400=3`，CRT 门闩释放标志为 1。这确认替代入口执行过；370 不命名为击杀数，8 不命名为死亡次数，计数不包含职业、技能或怪物身份。

## 脱壳状态

在两份 PE 原始数据共同覆盖区内找到 311 个精确符合 `push imm32; jmp 12EE7C9` 的旧跳板模式：仅 `13B37C2` 改写，其他 310 个仍保留相同十字节，见 [mainmodule-diff.json](mainmodule-diff.json)。这是限定范围与模式的比较，不能换算为恰有 310 个未恢复函数，也不证明它们执行过或共享分派器语义未变。可执行节内也含数据，整个节的变化字节数不是代码补丁数。

已完成导入修复、D 盘正常运行验证、运行快照和三处补丁归因。原版 OEP 的执行恢复、剩余保护语义、脱离启动器补丁及完整战斗控制器仍未完成。本次结论来自程序字节和运行现场，没有引入 `dnf-rebuild` 的战斗猜测。
