# 移植和后续适配

接手方可以直接以 `demo/src/main.cpp` 为最小可运行参考，再将职责拆到自己的引擎。推荐保持数据层、施法层、渲染层、命中层四个边界；先复现本包验收，再替换接口。

1. 资源层实现 `has/script/animation/pixels`，接受逻辑路径，返回有源身份的脚本、帧与RGBA。优先复用本包 `resources.cpp`，避免丢失IMG裁剪原点、链接帧或重复字段。
2. 技能层实现Cast/BodyStage/Track局部时钟和actor/spawn/cast锚点。按本包数据播放八技能，保留每个效果实例。后续恢复控制器时，将校准表换成事件/状态转换，不必改素材解码。
3. 人物层同步身体/装备帧，保留外观层顺序和武器独立攻击框。将移动和投影分别处理，不从武器像素边界推生成点。
4. 将攻击命中模块输出接到 `acceptedHit()`；目标generation、eventId、独立状态和死亡拒绝不能移除。替换固定伤害、HP和250ms策略时显式更新policy及测试。
5. 按MOB→ACT/ANI→ALS绑定当前版本的怪物动作。另一版本地址只能作为参考，不能当作该版本函数或字段布局。

跨鬼剑士职业：优先读取 `[skill fitness growtype]` 等已保存源字段；已有身体映射的技能可以采用相同ANI/ALS框架，但这些推导不是该技能控制器执行的证明。不能把崩山击的20050、123偏移或帧4触发复制给所有技能；可复用的是“来源ID→资源闭包→事件→坐标→独立实例”的方法。

其他大类角色：需要该族CHR、身体/装备路径、外观profile、技能表及成长分类；再绑定OBJ/PTL和运行分支。当前包只装入鬼剑士族当前可用流程所需IMG，不包含其他角色族完整资源。新增技能若引用包外图片，资产验证应失败或明确提示，不能静默替换近似素材。

REP：当前未确认其在技能释放链中的必要作用，没有REP解释器。不要为填补名称层面的“完整链”而虚构REP回放规则。后续采集应针对未闭合事件，复用现有规则覆盖同类技能，而非逐一手动拍图。

调试提交建议：保存F5反馈文件夹，附技能key、职业、武器、输入时序、预期和实际差异；如有新DLL采集，附源版本/profile及同一实例的请求/返回、坐标和绘制见证。以来源/实例校对问题，可以继续归纳通用规则。
