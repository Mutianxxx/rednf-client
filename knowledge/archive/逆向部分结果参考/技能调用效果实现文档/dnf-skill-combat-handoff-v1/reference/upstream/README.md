# 技能战斗演示 V1

双击工作区根目录的 **战斗技能演示.cmd**，或直接运行本目录 `battle_demo.exe`。独立 Windows 窗口，可以移动、连续普攻、释放技能、攻击三只怪物，播放受击及死亡。运行时读取本项目转换的 PVF 数据和 `../DNF/DNF/ImagePacks2`，无需 Python，也无需启动游戏或注入 DLL。

本版按用户允许的范围采用推理：保留实际调用已证明的规则，对缺少控制器的部分使用明确记录的重建规则。源 ANI/NPK 逐帧解码渲染；截图只用于反馈和验收，不参与效果实现。

## 操作

| 按键 | 功能 |
| --- | --- |
| 方向键 | 在场地内移动、改变朝向 |
| X | 太刀普攻，连续按或按住可连段；狂暴开启时改用 CHR 中的狂暴动作 |
| A | 崩山击 |
| S | 十字斩 |
| D | 怒气爆发 |
| G | 崩山裂地斩 |
| H | 血气爆发，本版采用已采集的固定持续与结束时序 |
| Q | 血气之刃，需要先开启狂暴 |
| E | 浴血之怒 |
| W | 开启/关闭血之狂暴，开启后 10 秒内不能关闭 |
| R | 重置人物、怪物、血量和效果 |
| M | 切换哥布林、猫妖、巨石傀儡，每种生成三个独立实例 |
| B | 显示身体/太刀/效果攻击框及怪物伤害框 |
| F1 | 打开/收起技能库 |
| Tab | 切换鬼剑士、剑魂、鬼泣、狂战士、阿修罗、全部职业的技能分类 |
| 技能库中的上下键/滚轮 | 选择技能 |
| Enter / 双击技能 | 释放选定技能；“待映射”项会提示缺少动作 |
| Space | 暂停/继续 |
| F5 | 导出画面、实例状态、动画帧、效果锚点、资源读取记录和构建指纹 |
| Esc | 收起技能库；再次按退出 |

先向右靠近第一只怪物，在同一横向通道按 X 或 S。A 会前移并在武器落点附近生成冲击波。大范围技能可对多个独立怪物生效。怪物死亡后按 R 重新生成。当前怪物作为攻击目标，没有主动追击或攻击玩家的 AI。

## 接入范围

技能目录保留原来的 231 条鬼剑士系记录、88 条主动技能及职业划分依据。战斗界面列主动技能；其中 8 条接入本轮采集链：崩山击、十字斩、怒气爆发、崩山裂地斩、血气爆发、血气之刃、浴血之怒、血之狂暴，共 179 个效果实例。其他已有身体映射的技能可按源 ANI/ALS 与既有资源关联规则推导演示；没有动作映射的技能保留诊断。**“实测链”表示使用了实机证据，不表示完整技能控制器已经恢复。** 嗜魂封魔斩按用户要求排除。

人物使用已采集外观配置和太刀资源；身体与武器共享身体帧索引。普通攻击的攻击框来自太刀 ANI，不能仅取身体 ANI。碰撞使用源攻击框与怪物伤害框的三维 AABB，按人物朝向镜像。对于只能取得屏幕投影位置的效果，其深度采用显式的平面重建，精确 XYZ 仍待补齐。

怪物配置从**当前技能客户端的同一份 packed PVF 快照重新解析**，并非把另一个版本的 MOB 绑定或原生地址直接搬过来。显示、受击和死亡参考用户提供的 `1031怪物受击死亡效果实现文档/dnf1031-monster-effects`：每实体独立时钟/HP/事件去重/死亡粒子；同一路径不同实例保留；没有明确末尾动作时使用文档的定格、白色轮廓、碎块、闪光、烟雾策略；有明确末尾 ACT 时读取 `[BASE ANI]`。声明但不可执行的死亡动作保留诊断，不静默换成其他死亡资源。

共享死亡的 60ms 白化、220ms 碎裂、90ms 主体淡出是交接文档的预览策略；碎块数量、重力、寿命、速度读取当前源 PTL。长受击 ANI 保留源时长，后续攻击可再次触发受击。巨石傀儡在当前源中未绑定两种受击动作，仍可扣血及播放明确死亡动作，日志记录缺失反应。

## 推导规则与边界

详见 [IMPLEMENTATION.md](IMPLEMENTATION.md)。主要区别如下：

- 崩山击的实体 ID、帧 4 触发、前方 123 偏移、前后四层、内部参数 27 对应水平距离 90，有源文件和保存的调用证据。起跳高度采用 SKL 端点插值，垂直弧线采用推导的抛物线；不补写未知上游 getter 的高度修正。
- 多层对象使用 OBJ/ALS/实际资源请求建立引用，区分“仅构造”和“确实绘制”。未恢复的控制事件采用本轮实际首次/末次绘制时序校准，并非通用原生分发器。大崩重复粒子的实例和开始时序保留，但粒子完整轨迹/随机生成器尚未恢复。
- 血气之刃的前冲采用 SKL dungeon static data 第 2 项及 charge 动作区间推导；结束爆炸保留实际创建链给出的高度。血之狂暴下的身体动作依据 CHR，完整常驻武器附层身份仍有缺口。
- 每个命中扣 100，怪物 HP 700，同一攻击实例/目标间隔 250ms；技能不扣蓝、不消耗物品、不执行原生冷却。多个源效果可能分别结算。这些是用于检验渲染和命中的演示规则。
- 血气爆发保持本次样本的固定持续时间，尚不按 H 的按住/松开动态改变阶段；浴血之怒 ALS 的负帧事件和一个不存在的 `sub_dodge.ani` 引用仍保留诊断。

## 验证与反馈

`reports/verification.json` 是可重复的自动验证结果；`reports/verification/` 保存验收画面与实例数据。检查包括方向/移动、左右镜像后的实际源攻击框扣血、输入失焦清理、连段、狂暴前置/10 秒关闭限制、崩山击落点、八技能效果采样、跨五个职业分类的推导演示、命中去重/过期 generation 拒绝、多实例隔离、共享死亡和独立死亡，以及按源时长返回待机。通过这些检查不等于全部目录技能运行通过。

发现效果不对时先按 Space 暂停，再按 F5；导出的 `reports/feedback-*/` 中有 `state.json`、`frame.png` 和 `build-manifest.json`。随后如需原客户端对照，可将该目录与新的 DLL 采集结果一并提供，便于核对具体阶段、源帧、锚点和推导规则。

构建及复验：

```powershell
& 'D:\ProgramData\anaconda3\python.exe' -X utf8 -B -S battle_demo/tools/prepare.py
& 'D:\ProgramData\anaconda3\python.exe' -X utf8 -B -S battle_demo/tools/build.py
& '.\battle_demo\battle_demo.exe' --verify
```

编译器及 SDL2/zlib 等依赖复用本机既有项目。旧技能浏览器、怪物演示器、游戏文件和采集 DLL 保持各自独立。
