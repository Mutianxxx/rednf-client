## 0. 首先明确交付边界

本文件不是画面设计稿，也不是凭截图绘制一套相似 UI。每条可采用的原生规则须追溯到本版 `DNF.exe` 的消费者，以及具体 PVF 字段或物理资源；无法闭合的关系保留未知。

**当前资料不能保证复刻“所有 UI 的全部图层、文字、动态状态和业务行为”。** 已提供全部 322 个 `.ui` 的配置和资源映射入口，以及已恢复消费者的可运行参考实现；但根窗口皮肤、部分专用控件、字体、ACT 调度、动态层序等尚缺原生契约。增加文档无法代替这些尚未完成的逆向。交付中的每个窗口都明确标记 `full_native_reconstruction=false`，不是隐去缺层后宣告完成。

可以直接使用的交付分为四层：

1. **静态输入**：322 个 UI 的原始解密字节、token、字段、控件、子 UI 边，以及完整 NPK 成员索引。
2. **原生规则**：通用加载/绑定/请求链、受限的图像几何和裁剪、board/loop、CBT/EVN 选帧、STM/WDM 结构及加载边。
3. **参考实现**：Python 配置/几何/证据模型，独立 C++ PVF/NPK/IMG/ANI 解码器，Qt 资源合成器。**Qt 预览不等于原生 GPU 渲染器。**
4. **机器映射与复核**：逐窗口/逐控件依赖表、原生代码切片、SHA256、离线验证和明确缺项。

不包含新的实机采集，不启动游戏、不执行游戏 VA、不注入、不部署采集 DLL。用户业务输入、服务器状态、人物装备等动态数据不能仅由静态资源推导。

## 3. 可追溯的资源链：不要丢掉任何一跳

推荐中间模型的追踪主键：

```text
EXE_SHA + PVF_SHA
  → PVF member path + decrypted_member_sha256
  → token offset / field offset / raw type+payload
  → UI load edge + instance + control offset
  → consumer VA / confirmed rule / state source
  → requested IMG path + requested frame
  → physical NPK archive + member offset + length + member_sha256
  → decoded RGBA + crop origin + logical size + png_sha256
  → ordered draw operation + transform + associated clip
```

同名路径、同帧图像可以共用像素，但不能共用控件状态和实例。缓存身份须包含物理来源和 decoder 身份；帧表链接不应改变请求的原始帧号记录。`handoff/animations.json` 对UI/配置直接引用的现存ANI提供逐帧姿态和IMG路径/帧，`ui-map.json.resources`包含这些间接IMG的物理候选；ACT内部调度链和模板运行替换不在该闭包中，缺项不补造。

### 3.1 PVF

参考源码：`combat_ui_1031/tools/pvf_reader.py`、`tools/pvf_inspect.py`、`monster_demo/src/resources.cpp` 的 `Pvf`。

- 目录和成员按既有 reader 读取。成员 offset 是 PVF 文件中的绝对偏移；checksum 用于该成员解密，不等同于 SHA256。
- 每个完整 little-endian DWORD：`v = rotate_right_32(raw ^ 0x81A79011 ^ checksum, 6)`；尾部和声明长度处理严格按 reader，不擅自填充语义字节。
- UI token 脚本保留前 2 字节头；之后每项为 `type:u8 + raw:i32_le`，总计 5 字节。`offset` 相对解密成员起点，首 token 常为 2。
- type 2 为整数、4 为 float32，5 为字段/命令；字符串型 5/6/7/8/10 的 raw 是 `stringtable.bin` 索引。**这个索引不是通用运行时文字 ID。**
- type9/10 是链接字符串路径，需经 `n_string.lst` 和相应 STR 的 key 解析；保留链接原文和来源，不能把 type10 单独当最终文字。
- 本版脚本文本按 CP936/GBK 严格核对，JSON 使用 UTF-8。RTF 是另一个来源，见第 10 节，不能一律套 GBK。
- 保留字段顺序、重复字段、作用域和未知 token；不能先转成字典覆盖掉原始列表。schema 的覆盖/清空/去重规则必须逐格式恢复。

`catalog/raw/<pvf path>.bin` 是解密原字节；`scripts.json` 的 `type/raw/offset` 能逐字节重组 token 区。`catalog/index.json` 增加便于 UI 使用的结构，并保留 `sha256/raw_file/pvf_entry`。重建 catalog 的顺序是 helper `catalog`、Python `controls()`、`catalog_evidence.py`；不要重新格式化后冒充原始字节。

### 3.2 UI 通用前缀

一个 `[ui controls]` 字段当前可识别的 counted prefix：

```text
type, name, x, y, string_count, strings[string_count],
integer_count, parameters[integer_count], trailing...
```

`parameters` 的含义取决于控件类型，**不可统一解释为帧号列表**。后随 `[parent] / [parent tab] / [parent page] / [parent radio]` 属于当前控件；`[string option] / [int option] / [common action]` 保存原文。遇 `[/ui controls]` 清除当前归属。

目录为 322 UI、4,013 控件记录；4,006 通用前缀可解码，7 个空/特殊块保留 raw。一个 UI 成员为空。前缀成功并不代表专用参数或控件行为恢复。

### 3.3 NPK 与物理来源

参考：`tools/assets.py::Assets.image/image_candidates`，C++ `Assets::Assets/blob`。

- 使用规范完整虚拟路径查索引，Python 层统一斜杠/小写；IMG 物理键没有 `sprite/` 时补此前缀。保留原路径拼写。不要仅按 basename 搜图。
- 1,654 个 NPK，90,848 物理条目，90,799 规范路径。NPK 同时含声音，不能把条目数称 UI 图片数。

- 冲突组默认拒绝。显式选择 `archive` 必须命中该路径的一条实际候选，并继续输出 `resource_ambiguity`。

- `source_reads` 中的 archive/offset/length/member_sha256 追溯此次请求，不混入 helper 前次读取。


### 3.4 IMG → RGBA 的中间契约

```json
{
  "resource": "interface/windowcommon.img",
  "frame": 213,
  "width": 12,
  "height": 13,
  "x": 0,
  "y": 0,
  "logical_width": 12,
  "logical_height": 13
}
```

这段尺寸取自实际 board 样本；PNG 路径/哈希和来源由每次解码输出，不手写。

- `width/height`：裁剪后像素尺寸；`x/y`：这些像素在逻辑图中的局部 crop 原点，可为负；`logical_width/logical_height`：未裁剪逻辑尺寸。
- 输出是 RGBA8。纹理不自动填充到逻辑大小；若自己做 atlas，须另存裁剪原点和逻辑尺寸。
- 解码器支持 IMG version 1/2/4；type17 是链接帧，防循环/越界；14/15/16 与 18/19/20 走相应16位/32位/调色板及 DXT 分支，原始/压缩 payload 由 mode 决定。**IMG 存储 type 与运行时 image/context `+8` 的类型不是同一个枚举。**
- 不应凭上述摘要重写不完整 decoder；移植 `decodeImg` 的长度、模式、调色板、链接、DXT 边界和透明度检查，未知版本明确拒绝。
- 空像素在 helper 当前作为 `empty image` 失败报告；不是在原生中所有空帧都必然报错的结论。

## 4. 原生 UI 对象、实例和绘制证据

```text
01067EC0 UI loader → 01064D20 token parser → 01074B70 配置工厂
  → 类型初始化 → 配置 +4 的实际控件 → 010669F0 绑定观察点
  → 011BF510 递归遍历 → vtable +24 类型专用绘制
  → 011B3950 / 011B41E0 图像请求 → IMG pack / frame → 资源解码
```

`011D5270` 的 `8B 41 04 C3` 只读配置 `+4`，不是实例工厂。文件路径、配置对象、运行实例、绘图上下文、源 IMG 必须分开建模。

源图像 `+64` 是 pack、`+68` 是帧索引。已核验 pack 虚表 `0185A380`，其帧表 `+58/+5C` 每项 16 字节，选中项首 DWORD 必须反指该图像对象；路径在 pack `+30` 字符串对象。没有这些关系的运行事件不应冒充已绑定 IMG。纹理指针 `+5C` 不能作为跨生命周期稳定 ID。

### 4.1 实例身份

- 静态：每条子 UI 加载边产生新 `instance`；控件 key 为 `instance + '#' + offset`。相同文件被加载两次，不合并。
- 运行：`session:control:pointer:generation`。generation 是已观察绑定代次，不是已完整恢复的构造/析构代次。
- 完整遍历缺席只记 `absent_from_this_traversal`，不宣布 hide/destroy。
- 窗口过滤按捕获 binding（path/span）和父控件祖先链，不靠“最近打开的 UI/IMG”或时间邻近。

### 4.2 有序操作

保留 `images/clips` 供旧代码读；新代码优先顺序遍历 `draw_ops`。运行操作的 `order` 是原遍历行号，可能有空隙；**不必连续，更不能按资源排序**。示意字段如下（具体值来自原事件）：

```text
draw_ops[] = {
  event, order, args, site, path, parent, object,
  instance:{pointer,generation,binding_revision,span},
  traversal_frame, source_event, draw_state
}
```

board 操作、配置 `config_image` 和原始 `image/clip_raw` 是三种不同来源，不能强塞成同一套 args。配置操作含 `path/frame/x/y/instance/source_event`；board 额外含 slot、crop、尺寸、缩放和消费者。

`draw_ops` 是已捕获请求顺序，不是完整 GPU 层序。运行时不叠加静态默认图片，否则会重复绘制或把已隐藏控件画出。静态 `static_controls` 仅按当前候选顺序合成，未证明所有控件原生 z-order，也未恢复全窗口管理器的层叠规则。

### 4.3 完整遍历条件

`FrameAssembler` 要求：首 `control.flags & 0x100`，结束 `tree_end` 丢失计数 args[0]==args[1]，事件数量等于 args[2]。未闭合、截断或队列溢出整次拒绝，不拼一个“完整窗口”。其完整只覆盖已布置入口，不包括所有专用画法。

## 5. 坐标、父级和根窗口

### 5.1 三套坐标分开

1. PVF 控件 x/y 和条件父级：在配置实例树求候选绝对锚点。
2. 运行请求 x/y：来自 `011B3950/011B41E0`，是已经更新的逻辑锚点，不再加配置父偏移。
3. IMG crop x/y：源图局部偏移，在变换前加到局部像素坐标，不是窗口世界位置。

静态求位置时，同一直接父控件若同时出现于 `[parent]` 和 `[parent tab]` 等标签，只累加一次位置；条件仍保留。条件是 `(parent_instance_key, selected_index)`，由本地/外部状态驱动。保留无法定位父级、循环、递归深度诊断。不要把 name 当全局唯一键。

子 UI 优先按完整 PVF 路径查找；找不到才相对于父 UI 目录规范化。子加载锚点的父坐标和条件继承一次，并生成独立实例。当前 `static_view()` 根原点固定 `(20,40)` 是**外部观察画布偏移**，不是 EXE 的窗口坐标；移植时可整体减去该值或由宿主提供根锚点。

根 `[tile type]/[size]/[alignment]/[window type]/[title string]` 原样保存在 `instances[].window_fields`。例如背包 `[size]=[20,31]` **不能按 20×31 像素画背景**；tile/边框/标题栏专用消费者尚未闭合。

### 5.2 几何公式（已核对消费者分支）

证据：`reports/geometry-revision6/evidence.json`、`reports/remaining-followup/evidence.json`；实现 `native_geometry.py::image_affine`。

简单入口 `011B3950`：三个参数 `x,y,image`。变换入口 `011B41E0`：九个参数 `x,y,image,sx,sy,rotation,color,cx,cy`。旋转以弧度保留。

对 PNG 像素位置 `(pixelX,pixelY)`：

```text
localX = cropX + pixelX
localY = cropY + pixelY
cosine = cos(rotation); sine = sin(rotation)
m11 = cosine * sx; m12 = -sine * sy
m21 = sine * sx;   m22 = cosine * sy
dx = cx - m11*cx - m21*cy
dy = cy - m12*cx - m22*cy
screenX = anchorX + m11*localX + m21*localY + dx
screenY = anchorY + m12*localX + m22*localY + dy
```

这对应负旋转，再按屏幕轴非等比缩放；Qt 六元矩阵顺序 `(m11,m12,m21,m22,dx,dy)`。不要换成先局部缩放再旋转的公式。普通静态/ANI 的 Qt 预览路径另有外部实现，不能将其推广为该原生请求公式。

中心参数按轴独立处理：

- float32 位模式 `99 76 96 7e`（约 `1e38`）：包装器换成源图逻辑宽/高的**整数半值**。
- `4294967296.0`（`00 00 80 4f`）：`011DB510` **只在 rotation==0** 时换成相应源图逻辑尺寸的整数半值；负零同属零分支。
- 非零旋转保留次级哨兵字面值，当前外部明确拒绝，不猜中心。
- 使用请求 `image_dimensions`；无此采集值才回退资源逻辑尺寸。**不是目的 context 的尺寸**。`011B41E5` 已把 ECX 从入口目的上下文改为源 IMG；`011DB510` ESI 是源 IMG，EBX 是目的 context。

运行变换颜色低字节 R、其后 G、B、高字节 alpha；包装器内的转换不要再重复做。参考实现对 RGB 做乘色、alpha 做 opacity。blend/shader/色彩空间的完整像素一致性仍未验收。

### 5.3 矩形与裁剪

`011B4710` 是 **ECX 目标对象成员 setter**，写 `+28/+2A/+2C/+2E` 四个 WORD：输入按 signed DWORD 解释，非正写0，正值只取低16位。消费者 `011B3680` 再按 signed WORD 扩展。

```text
word = max(0, signed32(raw)) & 0xffff
signedConsumerValue = word - 65536 if (word & 0x8000) else word
```

例如 `[-5,2,65537,0xffffffff] → [0,2,1,0]`。不能直接把原输入当最终屏幕矩形。

`011BF510` 根据控件 `+2AC` 和绝对 `+14/+18` 设置矩形，结束显式写回 `(0,0,800,600)`，**不是恢复父 clip**。因此不能把 `clip_raw` 解释成通用 push/pop 栈。

只在消费者核验、源图像布局和目的类型满足前提，且为单位变换分支时，用该条 image 的 `draw_state.rectangle_words` 对最终屏幕像素相交；右≤左或下≤上为空。截图范围/离线画布范围不是原生 clip。变换裁剪 `011B3690→0120EC70` 的 D3DX/state 语义未闭合，单独诊断，不能套轴对齐包围框近似并宣称正确。

### 5.4 源图像类型与目的 context 类型

- 已支持请求前提：`image_vtable==0x0185C76C`、源 `image_type==7`、`consumer_verified==true`；目的类型已知时须为7。旧包缺目的类型只保留旧的部分能力并提示证据不足。
- site7 的 `011DB180` 检查的是**目的 context +8**；8/14/15/16 路由 `011DADE0`，缺目的 surface/格式状态，当前拒绝近似。
- site8 直接变换虚调，不能误套 site7 的分派解释；捕获到非7目的时仍不冒充已实现。
- `payload_hex[+8]` 只有在 `draw_state.context==args[15]` 且字节范围完整时才恢复成 `context_type`。不可把源 `image_type` 复制成目的类型。

## 6. Board / draw by loop：可直接移植的原生布局

证据 `reports/board-followup/evidence.json`；配置 `01072820`，实例分派 `011EA1D0`，loop `011E9C30`，stretch `011E9E20`。参考 `board_layout.py`，不要采用早期 `preview_layout.nine_slice()` 的最大列宽/行高拟合来替代原生 board。

参数为恰好 11 个整数：前2是普通模式宽高或 loop 重复次数，后9是行优先帧。字符串第0项为 IMG，后续仅支持已确认的 `draw by loop`。

```text
slot:    0 1 2
         3 4 5
         6 7 8
Wi/Hi = slot i 的逻辑宽/高（不是 PNG 尺寸）
left=W3, right=W5, top=H1, bottom=H7
```

必须九图全部存在；中心逻辑宽或高为0则不画。各图 crop 独立参与绘制，不创建逐 cell clip，不剪掉越出名义 board 的像素。

### 6.1 Loop

前2项为 `countX,countY`，允许0。`width=W3+W4*countX+W5`，`height=H1+H4*countY+H7`。

从上到下 `countY+2` 行，每行从左到右提交：左图、`countX` 个完整中图、右图。首行槽0/1/2，中间行3/4/5，末行6/7/8。

```text
x: originX, originX+W3+column*W4, originX+W3+countX*W4
y: originY, originY+H1+row*H4,    originY+H1+countY*H4
```

均简单请求、无缩放、无余片补齐/裁切。操作数 `(countX+2)*(countY+2)`；0×0 为四角，并不是不画。

### 6.2 Stretch

```text
sx = float32((requestedWidth-W3-W5)/W4)
sy = float32((requestedHeight-H1-H7)/H4)
innerX = originX+W0
innerY = originY+H0
rightX = trunc_toward_zero(innerX + W4*sx + 0.5)
bottomY = trunc_toward_zero(innerY + H4*sy + 0.5)
```

注意扣边使用3/5、1/7，**内锚点却使用0号图**。任一 scale≤0 整板不画。右下取整在原始绝对坐标完成，不能先移到局部再四舍五入，尤其负原点。

锚点分别为 `(originX,innerX,rightX) × (originY,innerY,bottomY)`，按行优先提交九图；仅中间列用 sx，仅中间行用 sy；四角简单请求、其余零旋转/中心0/白色的变换请求。

合成位图取逻辑矩形与全部变换后 crop 像素的并集，floor 左上/ceil 右下，并保存此相对原点 offset。不可将并集左上当成新的控件 anchor。

参考实现安全上限：实际/逻辑范围4096、最多16,384操作、绝对锚点有界。这是外部内存预算，不是原生格式限制。真实 `ui/test/testbutton.ui` 的42,735提交被明确拒绝，不能截断后冒充全板。

## 10. ANI、ACT、文本与其它资源

### 10.1 ANI 资源采样

采用 C++ `decodeAni/Animation::samplePose` 与 Python `preview_layout.sample_animation`，保存 globals、逐帧 properties、duration、interpolate、pose、unsupported。输出弧度不预转度。缺属性依据全局/默认值重置，不从上一帧无限继承。

- 时长以毫秒。负/非有限外部时间归零；单次播放到末帧停留；循环是显式外部选项。
- 中间帧以半开时间区间选择；插值仅位置、缩放、rotation、RGBA。image/image_frame、flip、blend、碰撞框和事件保持离散。
- Qt 预览的加法 blend/LINEARDODGE 不等价完整原生 DODGE shader，effect_rgb及未实现属性保留。不要据Qt图给原生像素验收通过。
- ANI资源能解码不等于UI内的ACT触发、实例时钟、重复/停止、事件或混合链已恢复。

1,402原拼写图像引用路径=1,107格式模板+295字面路径；规范化后1,380，别名不丢。1,008模板有文件名候选，50,075是候选路径出现项，不是新增可绘制资源数。673,611条帧引用已有源ANI统计；运行格式参数仍未知，候选不能自动替换。295字面路径在NPK及散装IMG均无精确成员；44失败ANI为空字节。详见资源增量机器表。

### 10.2 标题、字体和动态文字

只把明确 `[title string]` 称为PVF来源标题；控件 `+48` 的字符串绘制不等于通用标题getter，不读取任意editbox内容。数字字符串ID不能用stringtable同号条目顶替。STR文字来源必须保留。

## 11. 诊断与离线包契约

六类诊断稳定保留：

| category | 含义 |
| --- | --- |
| `unknown_structure` | 未解前缀、控件schema、消费者或属性 |
| `unknown_state` | 配置之外的业务、输入、缺帧或选择状态 |
| `missing_resource` | 无精确资源、数字映射未知、帧越界或解码失败 |
| `resource_ambiguity` | 同路径不同内容，或明确选择但原生优先级未知 |
| `unconfirmed_geometry` | 父级/原点/变换裁剪等未确认 |
| `runtime_evidence` | 没有运行实例、绑定代次、目的类型或视觉验收 |

不要用一个“支持”布尔量替代 `identified / partial_replay / replayable / independently_rebuildable / locally_interactive` 各维度。手工点本地按钮不等于恢复游戏业务。

version1离线包主要字段：

```text
version, exe_sha256, pvf_sha256,
view, definitions, assets, animations,
failures, unresolved_assets, unresolved_animations, capability, limitation
assets[key]: file, png_sha256, resource, frame, width,height,x,y,
             logical_width,logical_height,source_reads,
             source_resolution?,cache_identity?,decoder_fingerprint?
view: draw_ops?,images,clips,controls,static_controls?,instances?,
      preview_diagnostics,board_previews?,configuration?,stage_id_index?
```

逻辑 asset key 是 `slash_lower(path)+':'+int(frame)`；目前不会自动合并带/不带sprite前缀的逻辑别名。`file` 是包相对路径；读包必须检查不越界和PNG SHA。`load_bundle`当前核对EXE/PVF身份、资产路径和hash；调用者应同时拒绝不支持的version。ANI元数据位于manifest内，包无需原PVF解码动画。新离线入口另存可选 `view.reference_selection`（tabs、external_time_ms、external_loop），重开时恢复本地选择，明确不是原生状态；显式命令行参数可覆盖。

所有新字段可选。旧包缺 `draw_ops` 时只能保留原 `images` 顺序/能力；没有上下文则不能补出 clip、中心或目的类型。原 `source_event/images/clips` 不被派生解析改写。`board_previews` 从原控件+元数据可重建；缺字段不是从历史事件补造实际运行状态。

## 12. 跨引擎最小实施顺序与验收
