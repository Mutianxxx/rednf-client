## 七、本轮踩坑（直接复用）

1. **`// 0x` 续行是最危险的坑**：任何注释行行首命中 `// 0xHHHHHH` 都会被解析成分隔行。
   两代事故：① 引用全局变量（`0x8F8520`）② 引用的 VA 恰好也是合法函数（`0x569F40`）。
   **规则：注释里引用任何地址一律写 `·0x`**。verify_refine 已有前置守卫。
2. **Git Bash / 本机 grep 不可靠**：`^// ` 模式在 ugrep 下静默失配——**行首扫描一律 Python**。
3. **代理的 md5 自证口径不一**：不同代理对「非注释行」定义不同。主代理复核用自己的
   Python 一行式（`[l for l in lines if not l.strip().startswith('//')]` 后 md5）。
   以 `verify_refine.py` 结构级判定为准。
4. **小尾巴（<5 函数）主代理亲做更划算**（本会话 broadcast_debug 尾部 4 个即如此）。
5. **shell heredoc 里的反引号会被展开**（写文档用 Python `<<'PYEOF'` 或纯 Write 工具）。
