# 00 范围、实现基线与证据管理

版本v1.1 · 2026-10-18 · 状态：设计待实施，文档已整理。

## 1. 最终交付与优先级

实现独立Windows C++17／SDL2客户端；正常运行只读取PVF与静态资源，不依赖原EXE进程。十个非缔造者职业以及本地1031实际开放的转职、觉醒、主动和被动全部进入最终门槛。实际分支由注册、学习资格、任务与控制器共同确定，不能按名称槽位开不存在的职业。缔造者仅延期运行时，其原始定义和依赖仍保存。

技能、装备、成长、战斗优先；城镇交互、商店、任务、副本、掉落、结算、返城与重载必须闭环。UI先满足这些操作和独立测试窗口，像素级全图层复现后续推进。按能力开放所有区域，不按地名编白名单。洛兰33份合法MAP作为回归集合，旧救援／拓扑不符两份来源继续保留，不因此加入普通池。

本轮采用离线本地服务。登录、组队、支付、社交等远程业务不由当前请求扩展为全MMO实现；其来源、接口和未支持状态必须列入模块表，不能显示虚假的可用功能。宠物、加工等本地功能按实际来源列能力；对十职业正常成长、转职或任务必需的部分不能以可选理由延期。

## 2. 十一条用户原则的工程解释

| 原则 | 本方案约束 | 验收落点 |
|---|---|---|
| U01 独立客户端 | PVF／1031资源作为内容；EXE仅作证据身份 | 独立包启动不运行原EXE |
| U02 通用逻辑 | 无地图／技能名称散落分支；专用控制器登记原因 | 行为能力、适配登记、代码审阅 |
| U03 来源渲染 | ANI/IMG/布局证据优先，确实缺源才重建 | 资源闭包和UI支持表 |
| U04 更换PVF | PVF和静态目录独立配置；兼容、缓存及存档绑定身份 | 跨配置与真实版本差异检查 |
| U05 核心完整且用户试玩 | 逻辑自动验证；不自行前台试玩 | 用户测试清单和反馈包 |
| U06 明确版本完成度 | 软件／内容／规则／schema分别版本化 | manifest、覆盖、已知问题 |
| U07 Beta独立窗口 | HP/MP锁、无CD、等级等通过命令提交 | 双窗口事件和数值消费者 |
| U08 成长及数值 | 成长、装备、攻速、伤害统一计算及trace | 端点、换装、取整、属性消费者 |
| U09 多推理可切换 | 每个候选有依据、默认、影响和生效时点 | RuleProfile、反馈关联 |
| U10 经验推理可推进 | 文件名／函数名可提供线索，不能冒充已证实 | 证据等级与运行能力分离 |
| U11 可玩交付 | 商店、交互、战斗、副本、任务、存档完整 | 正常模式端到端流程 |

逐条机器映射见[要求清单](appendices/requirements-traceability.json)。额外确认：全十职业门槛与按能力开放全区域均保持；文档落盘、丰富技术细节和核心伪代码也纳入清单。

## 3. 当前实现基线，不是未来完成声明

已有CharacterCatalog、CharacterIdentity、SkillKey、SkillSourceData与CharacterSkillState；默认装备由CHR／SD→EQU→LAY→ANI绑定。当前可玩仍主要为未转职鬼剑士，13主动与6被动仅局部；MP/CD仍消费首端点，完整成长、攻速和伤害公式未完成。其他九个职业存在来源模型不表示已可玩。

World仍含技能专用状态、演示数值；RegionCatalog仍固定少量区域、NPC与任务；AI存在路径分支。物件三层结构已经存在，应补齐消费者而非新建平行系统。存档有原子替换、备份、未知字段和相对时间基础，但尚缺完整事务、版本隔离和实体关系恢复。独立测试窗口尚未实现。

## 4. 证据分工与版本冲突

| 资料 | 用途 | 限制 |
|---|---|---|
| 当前PVF、NPK、audio.xml | 内容与资源身份 | 存在不等于语义或行为已实现 |
| combat-native-reverse分类报告 | 当前EXE局部调用链、帧、公式与碰撞证据 | 局部消费者不能扩展为全链证明 |
| 技能交接包 | 动作、效果、触发、实例及技术参考 | 部分为另一版本和重建，须逐项绑定 |
| 怪物效果交接包 | MOB→状态资源、独立／共享死亡、PTL参考 | 其PVF为ca756b…，2070绑定不是逐个运行验收 |
| UI交接包 | 322UI来源、控件几何与资源规则 | 同样ca756b…；所有窗口full_native_reconstruction=false；Qt非原生 |
| rednf研究 | 学习、奖励、维修、伤害与事务线索 | 缺原ELF同版证明；26／27伤害常量差异 |
| 安卓与Lua | 动作、独立武器、碰撞与局部消费者 | 不混编号、二进制布局、修改版数值 |
| 官方注释样例 | 字段含义、格式约束和已标未实现项 | 多年代；ANI相关部分为空，不提供二进制证明 |

UI／怪物包PVF完整历史身份：`ca756b7103a91628cffdf42fb745e9185fd5937deb229289a74831aa30500e1f`；其EXE：`246b838163fa7c71aa0445fa4aafde04e7ac72aa72855a4b2a7eaeed5eeae264`。带插件内存基线不能描述成无插件原版基线。

采用顺序：当前内容和同版已证消费者→核对过的参考行为→跨版机制线索→可验证经验重建。冲突必须记录字段、版本、原字节、选择理由、影响及替代策略。不得以同名自动建立跨版本身份。

## 5. 已确认覆盖旧记录的事项

- 旧“原生链全部confirmed才能实现新职业”改为允许完整可执行的inferred beta，同时保留证据不完整状态。
- 旧“自主前台测试”改为开发自动逻辑检查、用户前台观察；需要测试时交付步骤。
- 旧洛兰限定改为通用能力开放，保留洛兰历史合法集合回归。
- 旧65／240怪物HP、2x／3x倍率保留为命名的legacy测试策略。新正常模式由MOB和属性规则计算，默认不施加旧演示基数；旧运行快照不重新平衡。
- 用户指定死亡碎片最多700ms、末150ms淡出保留独立user-tuning，原生更短保留更短值，不能改源PTL。
- GBA旧平台配置（按键、CD、免材料、缩放）不进入Windows默认规则；旧工程禁用、原始资料只读等保护约定继续有效。

## 6. 完成状态与发布门槛

逐行为独立记录implementation（unsupported/partial/complete）、evidence（confirmed/inferred/unknown/user-tuning）、automatedVerification、userVerification、originalComparison。全技能complete可以含已明确标注的推理实现，不能含缺失伤害、被动消费者、清理或正常输入的占位。

没有经过用户前台验证的包可称“自动检查通过的可玩候选”，不得称用户验收通过。阶段候选不能代替最终全十职业交付。原版一致性是另一项验证，不能被beta可玩性吞并。
