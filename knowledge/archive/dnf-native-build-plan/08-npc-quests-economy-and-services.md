# 08 NPC、任务、经济、角色服务与离线边界

版本：v1.1；日期：2026-10-18；状态：设计待实施。

## 1. 基线与证据

[progression.hpp](../dnf-native-demo/include/dnf/progression.hpp) 已有买卖、装备、维修、药品、任务、掉落和通关接口，可保留facade逐步转发新服务。[progression.cpp](../dnf-native-demo/src/progression.cpp) 当前仍固定任务名单、48格、职业0奖励、250任务经验、击杀经验100×等级、金币20+5×等级、四个候选掉装ID及DGN1/2结算。这些不能作为通用内容。

[服务端研究](../dnf-result/docs/12-server-and-revised-android.md) 提供3222任务、当前PC20种条件类型/27服务端候选及奖励/修理/技能资格模型。服务端是独立版本候选；任务类别`[grade]`与条件类型`[type]`不能混淆。其原ELF未提供，不能声称已证实PC同版。

## 2. 服务拆分与NPC交互

`Progression`逐步拆为 `InventoryService`、`EquipmentService`、`EconomyService`、`QuestService`、`LootService`、`NpcService`、`CharacterLifecycleService`、`LocalCalendarService`。平台无关接口输入command和只读上下文，输出变更计划、诊断、显示信息，实际提交统一交 [10](10-persistence-and-migration.md)。UI不直接改金币、角色等级或任务JSON。

```cpp
TransactionPlan prepare(const PlayerCommand&, const GameSnapshot&, const ContentServices&);
QuestAvailability evaluateQuest(QuestKey, const CharacterContext&);
std::vector<NpcAction> availableActions(NpcKey, const InteractionContext&);
RewardPlan compileReward(const RewardSource&, const RewardContext&, RandomStream&);
```

NPC的商店、修理、技能学习、任务、仓储、加工等由源role/service编译。先验证交互距离、场景可见、清场限定和状态，再显示动作；提交时重查。台词/名字/声音从来源加载。事件NPC和死亡生成NPC用稳定spawn事件管理，不能只绘制出来却没有服务。

## 3. 库存、装备、货币与商店

物品实例使用稳定 `ItemInstanceId`，装备槽引用实例ID而非背包下标。物品定义来自EQU/STK，实例保存数量、耐久、强化/增幅/附魔、随机属性、绑定、期限和来源；只合并真正等价的可堆叠物品。容量、重量、最大叠数、使用资格由来源/版本策略决定；旧48格保留为历史策略，不宣称源事实。

重量以统一整数最小单位汇总，超重影响来自可切换策略；来源未确定时推荐禁止新增导致超限的拾取/交易，允许整理、卖出和卸下但不删除物品。装备变化统一重算属性/攻速/负重，坏损装备失效规则归版本策略。

商店解析真实售卖记录、价格、货币、数量、开放条件与随机商品；不能将每个整数都当商品ID。购买、出售、维修、药品使用均检查数量为正、余额、容量、资格和溢出。报价展示与提交重新计算使用同一规则；改变期间价格则返回新报价而非隐式扣另一金额。

维修优先核对服务端已隔离验证的整数除法→float32顺序，候选以版本标记。战斗磨损、死亡/撤退磨损、修理费用和装备损坏效果分别建规则，避免每tick错误扣耐久。药品扣数量与HP/MP恢复、共享CD同事务提交，不能恢复成功却未扣物品。

仓储实现角色仓库与来源明确时的账号仓库，转入/转出与背包同事务，保留绑定/不可转移规则。不存在账号共享语义时默认角色独立；不能因为本地20角色就允许任意共享。金币采用有界整数最小单位，计算采用更宽中间类型并检查溢出。

## 4. 任务与职业任务链

编译每个任务为资格表达式、条件树、事件订阅、提交消耗、奖励与重复策略。保留源grade/type、职业/成长限制、前置列表、NPC、原参数、难度/区域限制和未知项。实际出现的20种PC类型逐项建立执行器或明确未决，不能只处理见NPC/猎杀/通关三类。

条件支持AND/OR、计数、物品收集/提交、交谈、进入区域、杀敌、通关条件、装备/技能/转职和源特殊事件；具体是否消费物品由提交语义决定，观察库存不是立即吞材料。事件按任务实例与事件ID去重，取消/重接、重复任务周期生成新实例ID。

奖励支持固定、职业分支、选择、金币、经验、SP/技能或源支持的其他奖励。先预检完整奖励容量与所有消耗，再一次提交；不允许半发奖。任务经验表索引、难度权重、等级差惩罚、金币倍率分开实现，保留每一步整数截断；采用rednf候选时界面和日志说明版本依据。

所有十职业实际开放的转职和觉醒任务链都属于最终完整门槛，包括必需NPC、地图、道具、技能、特殊条件与奖励。阶段候选可以禁用未完成链，但最终不能以“能力未支持”规避交付。成长身份变更、技能资格刷新、属性重算、任务奖励和源要求的SP处理同一提交；不能仅修改job/growtype解锁。

```text
turnIn(requestId, questInstance, npc, selectedReward):
  重查任务状态、完整条件、NPC、奖励选择和当前内容版本
  预分配所需库存空间，编制材料消耗和完整RewardPlan
  在候选状态应用消耗/奖励/任务完成/成长变更
  写requestId结果及事件去重账本，提交同代快照
  提交后发布升级、任务完成和界面刷新事件
```

## 5. 掉落、结算与本地周期

`LootService`接收怪物死亡、物件、任务和结算的不同来源事件，解析对应掉落表，不用怪物击杀接口代理其他来源。先在候选快照抽取并保存具体结果、RNG、drop ID/位置和来源，再展示。满包保留未领取掉落；物品已领取标记、库存增加和地面实体移除同提交。

结算计算源经验、金币、翻牌/奖励、任务计数、耐久与疲劳；不再固定500×等级经验。普通失败、主动撤退、死亡、断线式退出（本地异常终止）分别记录，不能用失败重复结算。规则缺证据时给可切换候选，明确是否保留途中拾取/奖励及消耗时机。

疲劳、每日任务、限购、奖励次数、道具期限交 `LocalCalendarService`。默认使用保存的时区（初始Asia/Shanghai）和UTC时间戳生成周期ID，记录最后已处理周期；时钟回退不再次刷新，前跳仅应用一次当前周期。离线客户端不具备防系统改时的服务器权威，界面应说明本地规则，不虚构在线安全性。测试时间覆盖单独保存，不修改系统时钟。

复活使用源可用的消耗、次数、位置与恢复规则，未明项采用显式策略；耗材/次数与实体恢复同事务。疲劳、复活币、耐久、材料不得被默认测试无CD/锁血隐式豁免。

## 6. 扩展服务边界，避免漏项或承诺全MMO

| 服务 | 本轮要求与边界 |
|---|---|
| 强化/增幅/锻造/附魔/分解/合成/制作 | 先盘点PVF与本地资料。实现源可执行的配方、资格、材料、费用、概率、结果和属性消费者；随机结果同提交。必要职业/装备流程用到的服务必须完成。其余未明项明确禁用并列后续适配，不显示可操作空入口。 |
| 宠物/称号/时装/套装 | 保存完整物品和属性/外观来源；存在且参与正常角色属性的消费者纳入属性系统。宠物若有独立战斗行为按实体/技能能力检查，不能只有跟随贴图即称完整。 |
| 邮件/拍卖/交易/组队/公会/好友/PvP | 不扩为真实联网MMO。来源字段、UI角色和存档扩展保留；需要服务器/其他玩家的入口明确不可用。任务若依赖这些条件必须列明最终职业链影响，不能偷偷判完成。 |
| 本地账号与角色仓库 | 使用明确角色/账号命名空间与事务，不能绕过物品绑定；多人在线同步不在范围。 |
| 活动/商城/付费 | 只读保留来源；无本地合法可执行规则时禁用，不能伪造支付或实时活动服务。 |

## 7. P15子任务与验收

- **P15-S1**：物品实例、库存/货币/重量/装备和NPC角色；依赖P02来源/P05属性、P04事务。
- **P15-S2**：商店/维修/药品/仓储和加工能力矩阵；依赖S1。
- **P15-S3**：全部任务类型、奖励、职业链依赖图；依赖S1、P13世界事件、角色资格。
- **P15-S4**：掉落/结算/疲劳/复活/周期；依赖S2/S3、P13实体事件、P04快照；物件payload与P14在P18合并验收。

测试正反资格、错误NPC、边界数量、堆叠差异、满包、超重、金币溢出、重复请求、随机结果重试、并发点击、重接任务、选择奖励、周期回退和跨日；覆盖交易各提交边界故障。职业任务链自动图检查加用户完整试玩，最终交付报告逐链列完成状态。
