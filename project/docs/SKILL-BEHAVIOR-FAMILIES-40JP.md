# 40JP 技能行为族与复用设计

本文为 C++ 工程交接说明，回答两个问题：40JP 的技能表现是否有技能/技能族专用运行时逻辑，以及如何在保留共用引擎的前提下复用这些行为。

本文区分源码中直接观察到的事实、由事实支持的架构推测和后续实现建议。它不是完整的 40JP 技能清单，也不表示当前工程已经覆盖这些技能行为。

## 结论

40JP 体现的是“共用动画与对象机制 + 技能状态/行为族分支”。运行时分支选择 ANI、附着坐标、对象创建、缩放和命中条件；动画帧、图片、部分动作槽与参数仍来自资源或脚本。技能通常不需要各自重写一套渲染器，但也不能只靠读取 SKL 自动还原全部表现。

行为族应按执行机制划分，而不是按技能名称或视觉风格划分。例如：身体动作多段、人物附着特效、独立 PO/弹体、目标附着/抓取、持续区域效果、命中后条件特效、蓄力或持续施放。一个技能可以组合多个行为族。

## 40JP 直接观察

完整工作区的只读逆向源码中，可以复核以下格斗家调用点：

- 咆哮状态创建 `RoarStun1.ani` 与 `RoarStun2.ani`，并将它们挂到人物局部 Y=-65 的位置。见 `src/combat/bigfunc_5EA970_sub_5EA970.cpp:847,863`。
- 能量技能按子状态选择充能与发射路径：子状态 12/16 创建 `EnergyCharge.ani`，后续分支创建 `EnergyBallShoot.ani`。见同文件 `:1229,1274`。
- 背摔滚动阶段创建人物前后层 `JumpSuplexRollUnder.ani` 和 `JumpSuplexRollOver.ani`，缩放值依据被抓目标的尺寸计算。见同文件 `:1645,1661` 及相邻目标尺寸读取逻辑。
- 寸拳的 `ClosePunchExecute.ani` 以局部屏幕坐标 `(33,-49)` 附着。见同文件 `:1996`。
- 肩撞动作效果 `ShoulderTackle.ani` 与单独条件对象池中的 `ShoulderTackleHit.ani` 分开创建。见同文件 `:2211` 和 `src/combat/fighter_skills.cpp:2920`。
- 多个分支反复使用相同的动画资源构造与动画附着入口；同时也存在按变量拼接文件名的效果族，例如 ElementalChain 的阶段动画。

这些例子说明，运行时确实保存了资源文件本身无法表达的部分调用条件和附着行为。它们不足以证明所有格斗家技能，或所有职业技能都具有同样比例的专用逻辑。当前没有可靠分母可计算“需要专用分支的技能百分比”：代码按状态和行为族组织，一个分支可以服务多个技能，一个技能也可以跨多个状态和对象类型。

## 架构推测

以下判断与已观察到的调用点一致，但不是对所有 40JP 技能逐一审计后的结论：

1. ANI/图片的解码、动画时钟、对象池和附着绘制应由共用引擎负责；技能分支主要提供触发条件、资源引用、局部变换和生命周期策略。
2. 技能调用链并非必然完整写在 PVF。可见资料可能分布在技能注册、CHR 动作槽、ANI、ALS、NUT、ACT、OBJ/PO/PTL 和原生运行时代码中。运行时调用点可以补出“何时创建、对谁创建、如何变换”等关系。
3. 因此，“技能有专用行为”不等于“每个技能需要专用渲染器”。可复用的单位更接近行为族执行器和来源绑定的技能动作计划。
4. PVF 中相似的文件名、预加载图片或可解码 ANI 只能作为候选线索，不能单独证明播放时机、命中条件或坐标。

## 建议的实现模型

保持清晰的模拟与表现边界，并将来源证据放进动作计划：

- **行为计划**：职业入口、当前状态/子状态、阶段、触发类型，以及必要的命中或目标条件。
- **动作资源**：身体 ANI、武器/装备层、关联 ALS 和帧事件。
- **生成资源**：附着 ANI、draw-only 实体、PO/弹体、PTL；明确 owner、target、局部/世界坐标、缩放来源和生命周期。
- **攻击资源**：ATK/攻击框、攻击实例身份、重复命中策略和受击响应。纯视觉层不得直接造成伤害。
- **执行服务**：共用固定 tick、动画时钟、资源解析、实例生成/销毁、攻击事务和渲染采样；模拟执行事件，渲染只读采样结果。
- **诊断**：任何未解析调用、触发条件、资源歧义或 unsupported 命令都保留来源路径和具体原因，不以同名资源自动补齐。

## 后续工作顺序

1. 从 40JP 选择一项证据链清楚的代表技能，画出状态与事件序列：输入资格 → 状态/子状态 → 身体动作 → 附着或对象生成 → 攻击/命中 → 对象结束与清理。
2. 先整理行为族的共用接口，再为代表技能记录精确的来源调用、资源、条件、坐标和生命周期。不要先按全技能列表逐个复制代码。
3. 用代表技能验证执行器能处理该族的空放、命中、多段命中、目标失效和动作中断；通过后再把同族其他技能作为数据/调用描述接入。
4. 对运行时独有的规则保留来源函数与分支依据；对尚无调用依据的字段标记为假设，并设计可对比策略，不提升为事实。
5. 按技能族记录静态来源闭合、自动行为检查、画面/声音体验和原版动态比较。自动测试通过与用户观感符合是不同结果。

这条路线需要逐项确认技能或技能族的调用关系，但不要求为每个技能重新实现资源解析器、渲染器或伤害系统。个别技能若有独特状态机、PO 或目标关系，仍可提供窄的专用适配器，并复用公共执行服务。
